# Patient cockpit and shared timeline

Implemented locally on 8 November 2026 on `codex/stabilize-public-demo`.

**9 November update:** the visible local cockpit has since been connected to the actual fitted-model stack. See [Connected local demo](CONNECTED_LOCAL_DEMO.md) for the verified results and restart commands. The descriptions below of the disconnected preview refer to the separate preview implementation, not the currently connected local route.

## Purpose and audience

A researcher, with a clinician-facing interface, can inspect one synthetic patient's background, selected observation, meal-time result and subsequent follow-up without confusing those different sources of information. This is a research interface, not a physiological organ simulator or a clinical decision system.

## What changed

- The workspace now opens with an explicit synthetic-preview/demo label and separate patient-API and model status. A connected patient API does not imply available inference.
- A patient cockpit appears before the custom meal form. Fixed background and recorded meal are on the left, educational anatomy in the centre, selected glucose and the frozen meal result on the right. Smaller screens stack these sections.
- The existing recorded-history component owns one shared observation selection. The chart, scrubber, numerical readout, timestamp and before/at/after-meal label use that same selection. No additional prediction request is made when scrubbing.
- “At the meal” selects the actual baseline sample. “Latest follow-up sample” is disabled until a received post-meal sample exists. No fictional follow-up is generated by these controls.
- The displayed saved result comes from the latest journal record when present and retains its result ID. It remains unchanged during observation replay. Historical-attempt selection and reviews continue in the existing Follow-up section; the cockpit is explicitly the latest meal result, not a second historical-attempt selector.
- The existing completeness and event flags determine the follow-up summary. Incomplete data cannot be shown as a complete negative outcome. An event already seen in partial data is acknowledged.
- Three organ controls highlight an educational illustration and show the existing source-backed explanation of what is not measured. The main cockpit needs no WebGL; the existing 3D explorer remains available through “Explore in 3D” / “View patient twin.”
- Loss of the glucose stream clears the selected numerical readout and disables sample-jump controls. Fixed background and saved context remain inspectable.

## Boundaries

No training, dataset combination, new inference algorithm, physiological simulation or deployment is introduced. The local preview on port 5173 still deliberately returns unavailable scores. Real fitted-model operation requires the assembled backend and inference service. The full graphics/browser and assembled Docker acceptance gates remain open.

## Try it

Open the workspace, select a pre-meal sample, inspect the changed observation and unchanged meal context, then choose “At the meal.” Save an attempt, expand synthetic follow-up controls below, complete that labelled replay, and use “Latest follow-up sample.” The preview result remains unavailable; the later observations do not manufacture a score.
